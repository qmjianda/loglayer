### TD-004: LRU 缓存性能优化

**日期**: 2026-03-05
**状态**: 已通过
**类别**: 性能优化

#### 背景
原有的 LRUCache 使用 list 维护访问顺序，导致 `__getitem__` 和 `__setitem__` 操作中的 `remove()` 为 O(n) 时间复杂度。在高频访问的日志行缓存场景下，这会导致性能瓶颈。

#### 方案
- **方案 A**: 保持原有 list 实现
- **方案 B**: 使用 collections.OrderedDict 实现 O(1) 操作

#### 决策
选择 **方案 B**。使用 OrderedDict 的 `move_to_end()` 方法实现 O(1) 的访问更新，`popitem(last=False)` 实现 O(1) 的淘汰最旧项。

#### 后果
- **正面**: 缓存操作从 O(n) 优化到 O(1)，大文件滚动性能提升
- **负面**: 无，OrderedDict 是 Python 标准库

#### 后果
- **正面**: 提升用户体验，快速切换常见过滤场景
- **负面**: 增加少量代码复杂度

### TD-001: 虚拟滚动实现方案

**日期**: 2026-02-12
**状态**: 已通过
**类别**: 性能优化

#### 背景
LogLayer 需要支持百万行级别的日志文件，传统的 DOM 渲染会导致浏览器崩溃。

#### 方案
- **方案 A (DOM)**: 使用 React 虚拟列表库
- **方案 B (Canvas)**: 自定义 Canvas 渲染 + 虚拟滚动

#### 决策
选择 **方案 B**。

#### 理由
1. Canvas 渲染性能更好 (60fps vs 30fps)
2. 完全控制渲染逻辑，便于优化
3. 高 DPI 支持更精细

#### 后果
- 需要手动实现滚动同步
- 文本选择需要额外处理
- 学习曲线略高
