# history-file-path-storage Specification

## Purpose
让工作区文件历史以相对工作区根的路径持久化，使历史在跨平台
（Windows/Linux 分隔符差异）与工作区目录整体移动后依然可恢复，
无需任何平台相关的盘符映射或启发式转换。
## Requirements
### Requirement: 历史文件路径以相对路径存储

系统 SHALL 将文件历史中位于工作区内的条目路径存储为相对工作区根的
POSIX 风格路径（`/` 分隔符）；无法相对化的条目（工作区外或跨盘）
MUST 以绝对路径原样存储。

#### Scenario: 工作区内文件存为相对路径

- **WHEN** 用户在工作区内打开文件 `logs/app.log`（绝对路径为
  `<root>/logs/app.log`）
- **THEN** 该文件的历史条目路径被存储为 `logs/app.log`（不含盘符、
  不含 `/mnt` 挂载点、使用 `/` 分隔符）

#### Scenario: 工作区外文件存绝对路径兜底

- **WHEN** 用户打开的文件位于工作区根之外（相对化会产生 `..` 溢出）
  或位于不同盘符（相对化无意义或不可能）
- **THEN** 该文件的历史条目以绝对路径原样存储
- **AND** 存储过程不抛异常，不影响其他条目的写入

### Requirement: 历史路径读取时惰性兼容

系统 SHALL 在读取文件历史时区分相对与绝对路径：相对路径基于当前
工作区根解析为绝对路径，绝对路径（旧数据或兜底条目）MUST 原样使用；
两者 MUST 共存于同一存储且互不干扰。

#### Scenario: 相对路径拼工作区根解析

- **WHEN** 历史条目路径为 `logs/app.log` 且当前工作区根为
  `<root>`（当前平台的原生绝对路径）
- **THEN** 系统将该条目解析为 `<root>/logs/app.log` 用于打开文件

#### Scenario: 绝对路径旧数据原样使用

- **WHEN** 历史条目路径为旧版本写入的绝对路径（如 `D:\logs\a.txt`
  或 `/home/user/logs/a.txt`）
- **THEN** 系统将该路径原样用于打开文件，不做任何平台转换
- **AND** 解析过程不抛异常

#### Scenario: 跨平台后相对路径仍可解析

- **WHEN** 历史存储于 Windows 平台写入（相对路径 `logs/app.log`），
  随后用户在 Linux 平台打开同一工作区目录并指认其为工作区根
- **THEN** 系统以 Linux 分隔符将条目解析为 `<linux_root>/logs/app.log`
- **AND** 平台分隔符差异由系统路径 API 自动处理，无需手工转换

### Requirement: 路径失效时非静默失败

系统 SHALL 在历史路径解析后文件不存在时返回打开失败并输出明确
提示；系统 MUST NOT 自动递归扫描工作区来寻找同名文件。

#### Scenario: 失效路径提示而非扫描

- **WHEN** 历史条目解析后的绝对路径不存在，且工作区中存在同名文件
- **THEN** 系统返回打开失败
- **AND** 输出包含文件路径的失败提示（如 `[Bridge] File not found: ...`）
- **AND** 系统不发起任何工作区目录递归遍历

### Requirement: 书签随路径相对化持久化

系统 SHALL 将书签持久化键基于该文件的历史存储路径（相对或绝对，
与 files 表一致）而非打开时的会话绝对路径，使跨平台或工作区移动后
书签仍可恢复。

#### Scenario: 跨平台后书签可恢复

- **WHEN** 用户在 Windows 平台为 `<root>/logs/app.log` 添加书签，随后
  在 Linux 平台指认同一工作区目录为根并重新打开该文件
- **THEN** 系统能从持久化存储恢复该书签
- **AND** 恢复的书签行号与添加时一致

#### Scenario: 工作区外文件书签仍按绝对路径持久化

- **WHEN** 用户为工作区外的文件（历史存储为绝对路径）添加书签
- **THEN** 书签持久化键基于该绝对路径
- **AND** 重新打开同一绝对路径文件时书签可恢复

### Requirement: 打开单文件时以文件所在目录为工作区根

系统 SHALL 在未设置工作区的情况下打开单个文件时，将该文件所在目录
作为工作区根（`.loglayer/` 持久化目录随之建于此目录下），使单文件
场景的历史存储与多文件工作区场景行为一致。

#### Scenario: 单文件打开建立工作区根

- **WHEN** 系统启动后直接打开单个文件 `D:\logs\app.log` 且此前未设置
  任何工作区
- **THEN** 系统以 `D:\logs` 为工作区根建立持久化存储
- **AND** 该文件的历史条目存储为相对路径 `app.log`

#### Scenario: 单文件打开不改变已有工作区

- **WHEN** 工作区已设置为 `<root>` 后打开位于该工作区内的文件
- **THEN** 系统不改变当前工作区根
- **AND** 该文件的历史条目存储为相对该工作区根的路径
