description: 一人公司 - 回归/评审阶段（validate + 测试 + 静态门 + 越界检查 + 汇报）
---

一人公司模型的**回归闸门**：验证实现是否满足 DoD，并生成汇报材料等老板交付审批（Gate 2）。

**输入**：`/company-review <变更名>`。若省略，检查对话上下文；歧义则 AskUserQuestion。

**步骤**

1. **选择变更并检查状态**

   ```bash
   openspec-cn status --change "<name>" --json
   ```
   确认产出物齐全、实现任务已勾选；缺失则提示先跑 `/company-spec` 或 `/opsx-apply`。

2. **OpenSpec 合规验证**

   ```bash
   openspec-cn validate <name>
   ```
   失败 → 修复产出物后再继续（≤3 次，见熔断规则）。

3. **运行相关测试**

   ```bash
   python3 -m pytest tests/unit/ -k "<name关键词或能力名>" -v   # 验收 + 相关单测
   python3 -m pytest tests/integration/ -v                     # 受影响集成测试
   ```
   UI/交互类变更追加：
   ```bash
   npm run e2e -- --light
   ```
   **证据制**：记录实际输出（通过/失败计数），禁止口头声称。

4. **静态门**

   前端改动：`npx tsc --noEmit`
   后端改动：`ruff check backend tests`

5. **越界检查（归属并集判定）**

   **前置校验**：确认 `openspec/changes/<变更名>/scope.md` 存在；缺失 → 提示先回归规格阶段生成登记表，不直接误判改动文件。

   收集改动文件：
   ```bash
   git status --short
   git diff --name-only
   ```

   归属并集判定（对照**所有活跃变更**的 scope.md）：
   1. 读取本变更 `scope.md`（`openspec/changes/<变更名>/scope.md`）
   2. 经 `openspec-cn list --json` 获取活跃变更清单，逐一读取其他活跃变更的 scope.md（缺失的按"无登记、不参与并集"处理，并在汇报中提示）
   3. 对每个改动文件做三类判定：
      - **命中本变更 scope** → 本变更工作，放行 ✓
      - **未命中本变更但命中其他活跃变更 scope** → 其他变更的进行中工作，标记"其他变更工作，非越界"，**不升级**
      - **未命中任何变更 scope** → 无归属 → **升级给老板**（越界风险），附 diff 清单与判定依据
   4. 汇报中输出归属判定结果：本变更文件 / 他变更文件（非越界）/ 无归属文件（已升级）

6. **熔断规则**

   步骤 2-5 中**同一闸门连续失败 3 次** → 停止自动重试，升级给老板：
   - 附失败证据（测试输出/报错）
   - 附可能原因与建议方向
   - 等待老板决策（继续排查 / 修改实现 / 调整规格 / 放弃）

7. **DoD 核对 + 汇报**

   对照 DoD 清单逐项核对（产出物齐全 / 验收红→绿 / 测试通过 / 静态门干净 / validate 通过 / 无调试输出 / UI 变更 e2e 通过）。

   生成落盘报告：`docs/company-reports/<变更名>-<日期>.md`
   ```
   ## 回归阶段完成：<name>
   - 阶段: 回归通过
   - 改动摘要: <文件清单 + 主要变更>
   - 测试证据: pytest N passed / e2e N passed（附输出摘录）
   - 静态门: tsc/ruff 通过
   - 越界检查: 无越界（或已升级）
   - DoD: N/M 项满足
   - 风险与待决策项: <列明>
   ```

8. **闸门暂停，等待老板（Gate 2）**

   展示一屏摘要并询问老板：
   > 回归全部通过，报告已落盘 <路径>。是否批准交付（合并/归档）？或打回修改？

**护栏**
- 只验证与汇报，**不修改实现代码**（除非修测试/产出物本身）
- 汇报必须附证据（测试输出/diff），禁止无证据声称通过
- 越界与连败必须升级老板，不自行消化
- 老板未批准前不归档、不合并（draft-only）
