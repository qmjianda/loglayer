description: 一人公司 - 一键跑完整循环（评审→规格→红→实现→回归→汇报）
---

一人公司模型的**完整开发循环**：设计评审 → 规格产出物 → 验收测试（红）→ 实现（绿）→ 回归 → 汇报，闸门处暂停等老板。

**输入**：`/company-run <变更名>`。若省略，检查对话上下文；歧义则 AskUserQuestion。

**前置条件**：老板已用 `/company-init` 批准立项（Gate 1）。若未立项，先完成立项再运行本命令。

**步骤（按顺序执行，等价于依次调用 company-spec → 实现 → company-review）**

1. **规格阶段**（同 `/company-spec <name>`）
   - grill-me 设计评审闸门（不过不放行）
   - 生成 OpenSpec 产出物（proposal → specs → design → tasks）
   - 验收测试从 specs 场景落地并确认**红**

   **闸门暂停 1**：规格定稿汇报 → 询问老板"继续实现 / 调整规格"。
   老板说继续才进入实现。

2. **实现阶段（绿）**（同 `/opsx-apply <name>`）
   - 读取产出物上下文
   - 逐个任务实现，保持最小且聚焦
   - **每完成一个任务立即更新 tasks.md checkbox**
   - 先让验收测试变绿，再处理其余任务
   - 卡壳/歧义 → 暂停询问老板，不猜

3. **回归阶段**（同 `/company-review <name>`）
   - `openspec-cn validate`
   - 相关测试（pytest）+ UI 变更 e2e
   - 静态门（tsc / ruff）
   - `git diff --name-only` 越界检查
   - 熔断：同一闸门连败 3 次升级老板
   - DoD 核对

4. **汇报 + 闸门暂停 2（Gate 2）**

   生成落盘报告：`docs/company-reports/<变更名>-<日期>.md`

   展示一屏摘要（改动、测试证据、DoD、风险）并询问老板：
   > 循环完成，报告已落盘 <路径>。是否批准交付（归档/合并）？或打回修改？

   老板未批准前：不归档、不合并（draft-only）。

**输出模板（每阶段切换时）**

```
## 一人公司循环：<name>
[1/4] 规格阶段    → ✅ 评审通过 / 产出物就绪 / 验收测试红
[2/4] 实现阶段    → ✅ N/M 任务完成 / 验收测试绿
[3/4] 回归阶段    → ✅ validate / 测试 / 静态门 / 越界 全通过
[4/4] 汇报        → 报告: docs/company-reports/<name>-<date>.md
```

**护栏**
- 顺序不可跳：评审 → 规格 → 红 → 绿 → 回归 → 汇报
- 每道闸门暂停等老板，不自动推进越过闸门
- 实现阶段卡壳即问、回归连败即升级
- 老板未批准交付不合并/不归档
