description: 会话模板 - Bug修复/新功能/重构/评审 结构化任务模板（配合 openspec 工作流）
---

LogLayer 会话模板，与 OpenSpec 工作流配合使用。新会话按 `AGENTS.md` 的"新会话启动"指引建立上下文后，按任务类型套用以下模板。

**上下文建立：**
1. 阅读 `AGENTS.md`（概况、规则、架构地图、导航）
2. 运行 `openspec-cn list --json`（活跃变更与进度）
3. 按任务类型进入对应深潜文档或代码

---

```markdown
- **实际**: [描述实际发生的问题]

### 最小复现步骤
1. 
2. 
3. 

### 错误信息
```
[粘贴错误信息]
```

### 相关代码
- 文件: 
- 行号: 

### 约束条件
- [ ] 不能修改 X 功能
- [ ] 必须保持 Y 行为

### 验收标准
- [ ] 附带最小复现测试（tests/repro/ 或单测）
- [ ] 无测试不闭环
```

## 模板 B: 新功能开发（走 openspec 变更）

```markdown
## 本次任务: [功能名称]

### 功能描述
[一句话描述功能]

### 用户故事
作为 [用户类型]，我希望 [功能]，以便 [收益]。

### 变更要求
- 使用 `/opsx-new <change-name>` 创建变更
- 依次完成 proposal → specs → design → tasks
- 实现后逐个勾选 tasks，最后 `/opsx-verify` 与 `/opsx-archive`

### 边界情况
- 情况 1: 
- 情况 2: 

### 验收标准
- [ ] 功能完整可用
- [ ] 无 TypeScript 错误（npx tsc --noEmit）
- [ ] 遵循代码风格（见 AGENTS.md）
- [ ] 包含必要测试
- [ ] 变更已归档到 openspec specs/
```

## 会话结束检查清单

- [ ] 代码修改已完成
- [ ] TypeScript 编译通过（`npx tsc --noEmit`）
- [ ] 功能测试通过（如适用）
- [ ] 每完成一个 task 已勾选对应 checkbox
- [ ] 新决策已记录到变更的 design.md（而非旧 ADR 文档）
